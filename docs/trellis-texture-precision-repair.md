# TRELLIS texture precision repair (2026-10-19)

The owner asked to fix the scuffed generated appearance, and also requested clickable avatar cards with current status. This work runs one explicitly authorized source experiment at a time; it does not re-enable visual automation or ML, restore cleared reports, regenerate the roster, or publish a model.

## Confirmed local defect and correction

The deployed low-memory pipeline used Q4_K_M for both geometry and texture flow. A matched local control confirms that the **512 texture flow loses reference-consistent colors at Q4_K_M** on this installation. With the same mesh, frozen reference, seed 25001, 12 texture steps, 512 resolution, 1024 texture atlas and texture-processing code, the Q4 control produces rainbow patches while Q8_0 produces coherent white/gold armor. This is a visual finding from actual exported meshes, not an arbitrary beauty score or a guarantee of perfect anatomy for every input.

Actual comparison: `trellis-texture-comparison.html`, `trellis-texture-q4-control.png`, `trellis-texture-q8-result.png`. The render script uses Blender's texture display, not an image generator, repaint or replacement concept image. Earlier upstream reports were diagnostic leads; this matched local control establishes the precision defect here. Related upstream report: https://github.com/visualbruno/ComfyUI-Trellis2/issues/182 .

Default **512** generation now keeps Q4_K_M sparse/shape models but uses the separately pinned **Q8_0 texture flow**. Sampling settings, geometry weights and limits are unchanged. The 1024 pipeline has not been qualified by this change. `patch_nodes.py` applies a constrained selection change only at the reviewed 512 texture-loader site, after checking the exact upstream source hash and expected occurrence counts. Model URLs are never accepted from job requests and inference stays offline.

Q8 checkpoint: `Aero-Ex/Trellis2-GGUF`, revision `edf81aef93af0823ac8721da3c9cd3c52d539f87`, `texture/slat_flow_imgshape2tex_dit_1_3B_512_bf16_Q8_0.gguf`, 1,426,451,744 bytes, SHA-256 `ed803025b96c609db6dbbf65ab3cc676d3fedab3cdc6231e67a3e085e5f421f0`. ## Retexturing integration and resource evidence

`texture_pilot.py` is an owner-invoked diagnostic CLI for a UUID-identified preserved source. It verifies the source hash, freezes a separate experiment plan/workflow, uses the shared exclusive GPU lease, disables network access during inference, samples resources and applies the existing 4,608 MiB anonymous-memory / 11,000 MiB sampled GPU / deadline limits. It exposes no arbitrary-workflow HTTP endpoint and never restores Laravel reports.

The first attempt rejected an unsupported texture tiled-decoder method. The second direct-decoding attempt hit the existing RAM guard and stopped without output. These failures were retained. The reviewed fix to the upstream single-mesh texturing path derives the same sparse subdivision guidance used by normal image-to-3D decoding, discards the unused reconstructed guide mesh, and releases the local texture-model reference before decoding. That prevents unguided expansion/model retention from defeating offload. The corrected texture-only Q8 and Q4-control runs both completed under the unchanged sampled resource guards. This is not a hardware peak-memory or device-FPS claim.
